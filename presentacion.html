Contexto y Objetivo

¿Por qué este trabajo?

🌐
Motivación

En el paradigma IoT, la geolocalización es un requerimiento fundamental. Los drivers de alto nivel de ESP-IDF ocultan cómo interactúa realmente el procesador con el hardware.

🎯
Objetivo

Diseñar un sistema híbrido que evidencie el control real sobre la arquitectura: lectura directa de registros RISC-V + lógica de alto nivel en C.

Requisitos de la consigna
  • 📡 Recepción de datos del módulo GPS por UART1
  • 🖥️ Interfaz de usuario limpia por UART0
  • 💡 Tres LEDs como indicadores de estado del proceso
  • ⚙️ Rutinas en Assembler RISC-V para el hardware
  • 🗺️ Mostrar coordenadas, altitud o velocidad a elección

Rutina de lectura FIFO en RISC-V

info_gps:
  li t0, UART1_STATUS_REG
  lw t2, 0(t0)
  andi t2, t2, 0x3FF // máscara
  beqz t2, no_hay_datos
  li t3, UART1_FIFO
  lbu a0, 0(t3) // unsigned
  ret
no_hay_datos:
  li a0, -1
  ret

Lógica inversa en Assembler

Los ánodos van a 3.3V. Para encender: escribir 0 en GPIO (GPIO_OUT_W1TC_REG). Para apagar: escribir 1 (GPIO_OUT_W1TS_REG). Esto evita reasignar pines con funciones especiales.

Discusión y Conclusiones

Análisis y aprendizajes

Polling: decisión justificada

A 9600 baudios el microcontrolador puede atender la FIFO sin pérdida de datos. Sin embargo, si se aumentara la velocidad o se incorporaran más periféricos, un diseño basado en interrupciones o DMA sería más apropiado.

Arquitectura híbrida: beneficio real

Separar la capa de Assembler (FIFO + LEDs) de la capa C (parsing + lógica) mantuvo el código modular y legible, sin perder control sobre el hardware.

  • Sistema embebido funcional con comunicación GPS en tiempo real
  • Lectura directa de registros RISC-V sin depender de abstracciones del SO
  • Parsing carácter a carácter robusto con protección ante desbordamiento
  • Validación de fix GPS: el sistema no muestra datos inválidos sin señal
  • ESP-IDF demostró facilitar la coexistencia de C y Assembler en sistemas embebidos complejos
